# KeyRemap

一个 Windows 原生的小工具：当笔记本的数字键或功能键坏掉时，用 QWERTY 行顶替它们。

按 `Ctrl+Alt+M` 在三种模式间循环切换，屏幕顶部会弹出半透明提示告诉你当前模式，右下角托盘图标也会变色。

---

## 它解决什么问题

笔记本的键帽是一体的，数字键排或 F 功能键排一旦损坏，整排都按不出来，换键盘成本高（往往要换整个 C 面甚至主板）。

KeyRemap 把**好的那一排**（`Q W E R T Y U I O P [ ]`，共 12 个键）借给坏的那一排用：

- **数字模式**：借给数字排 → `1 2 3 4 5 6 7 8 9 0 - =`
- **功能模式**：借给 F 键排 → `F1`~`F12`
- **正常模式**：物归原主，一切照旧

12 键对 12 键，正好一一对齐。

---

## 映射表

| 物理键 | 正常模式 | 数字模式 | 功能模式 |
|:---|:---:|:---:|:---:|
| `Q` `W` `E` `R` `T` `Y` `U` `I` `O` `P` | 原样 | `1` `2` `3` `4` `5` `6` `7` `8` `9` `0` | `F1`~`F10` |
| `[` | 原样 | `-` | `F11` |
| `]` | 原样 | `=` | `F12` |

**Shift 变体自动生效**：数字模式下 `Shift+Q` 得到 `!`，`Shift+P` 得到 `)`，`Shift+[` 得到 `_`（因为 Shift 本身没有被拦截，注入的数字会自动带上移位符号）。

## 使用

### 下载

到 [Releases](https://github.com/Canny345/KeyReMap/releases) 下载 `KeyRemap.exe`，双击运行即可。

**单文件、零依赖** —— 不需要安装 .NET、AutoHotkey 或任何运行库，约 160 KB。

### 操作

| 操作 | 效果 |
|:---|:---|
| `Ctrl+Alt+M` | 循环切换 正常 → 数字 → 功能 → 正常 |
| 托盘图标右键 | 弹出菜单：查看当前模式 / 切换模式 / **设置热键…** / 退出 |
| 托盘图标双击 | 切换模式 |
| 托盘图标颜色 | 灰 `N` = 正常，蓝 `1` = 数字，绿 `F` = 功能 |

### 自定义切换热键

托盘图标右键 → **设置热键…** → 直接按下你想用的组合键 → 保存。立即生效，并写入 exe 同目录的 `KeyRemap.ini`：

```ini
[Hotkey]
Mods=3      ; 1=Alt 2=Ctrl 4=Shift 8=Win（可相加）
VK=77       ; 虚拟键码，77 = 'M'
```

热键**必须包含 Ctrl / Alt / Win 中的至少一个**（只按 Shift 或裸键会与正常打字冲突）。若设置的热键已被其他程序占用，会提示并保持原设置不变。删掉 `KeyRemap.ini` 即恢复默认的 `Ctrl+Alt+M`。

### 提示框

屏幕**顶部居中**弹出，半透明圆角，不抢焦点、鼠标可穿透（不会挡住下面的内容）：

- **切换模式时**：显示当前模式，约 1.3 秒后自动消失
- **按键生效时**：显示 `Q → 1` 这样的对应关系，**按住保持、松手立即消失**

## 设计上的几个取舍

- **热键默认是 `Ctrl+Alt+M`，不是 `Shift+Tab`**：`Shift+Tab`（反向跳格）在浏览器表单、编辑器里都是常用键，占用它会破坏正常操作。热键可在源码顶部的配置区修改。
- **按住 Ctrl / Alt / Win 时一律不拦截**：只映射裸键（可以带 Shift）。所以 `Ctrl+W`（关标签页）、`Ctrl+R`（刷新）、`Ctrl+C` 这些组合键完全不受影响——它们的键盘替代品不好找，而 `@` `$` 这类字符用 `Shift+W` / `Shift+R` 就能打出来（Shift 不拦截，注入的数字会自动带上移位符号）。
- **正常模式下不安装任何映射**：此时程序对键盘零干预。
- **只忽略自己注入的按键**：用 `dwExtraInfo` 打标记区分，不会误伤其他自动化工具或输入法注入的按键。
- **屏幕几何全部按比例计算**：提示框尺寸依据当前显示器**工作区**（而非整屏）按比例算出，自动适配任意分辨率、缩放比例和任务栏位置，换机器无需改任何数值。

## 从源码编译

### 原生 C++ 版（推荐）

需要 Visual Studio 2019/2022 的 C++ 工具链（含 Windows SDK）。

```cmd
build_cpp.cmd
```

产物：`dist\KeyRemap.exe`（`/MT` 静态链接 CRT，零依赖）

### AHK 原型版（已由 C++ 版取代，保留作参考）

需要 [AutoHotkey v2](https://www.autohotkey.com/) 和 [Ahk2Exe](https://github.com/AutoHotkey/Ahk2Exe)，放到 `tools\AutoHotkey\` 与 `tools\Ahk2Exe\` 下，然后：

```cmd
build.cmd
```

产物：`dist\KeyRemap-ahk.exe`（约 1.2 MB，内嵌解释器）

> `tools\` 目录未纳入版本管理（第三方二进制体积较大），需要时自行下载。

## 技术实现要点

**键盘钩子**：`SetWindowsHookEx(WH_KEYBOARD_LL)` 全局低级键盘钩子。命中映射表时返回 `1` 拦截原始按键，再用 `SendInput` 注入目标按键。

**避免死循环**：注入的事件会再次经过自己的钩子。用 `dwExtraInfo` 打上专属标记，只忽略带标记的事件——这样既能防死循环，又不会误伤其他程序注入的按键。

**提示框**：`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` 的弹出窗口，配合 `UpdateLayeredWindow` + GDI+ 做**逐像素 Alpha**——背景半透明（能透出桌面内容），文字完全不透明（保持锐利）。

> 如果用整窗均匀透明（`SetLayeredWindowAttributes`），文字会跟着一起变透明，边缘发虚。这是本项目改用逐像素 Alpha 的原因。

**松手判定**：以钩子收到的 `keyup` 事件为准。

> ⚠️ 这里有个坑：**不能用 `GetAsyncKeyState` 轮询物理键状态**。钩子返回 `1` 拦截后，该按键不会进入系统输入队列，异步键状态永远读不到它，导致提示框刚弹出就被误判为"已松开"而立即消失。

**DPI 与坐标**：进程声明 `PerMonitorV2` DPI 感知，坐标全程使用物理像素，避免多屏不同缩放下的错位。

## 常见问题

**Q：会被杀毒软件报毒吗？**

有可能。这类"全局键盘钩子 + 模拟按键"的工具，行为特征与键盘记录器相似，启发式引擎容易误判。原生 C++ 版（无内嵌解释器、无自解压层）的误报率明显低于打包成 exe 的脚本程序。若被拦截，将该文件加入白名单即可。

**Q：游戏里能用吗？**

大部分游戏可以。少数带**反作弊**机制的游戏、以及使用 Raw Input 的程序可能收不到模拟按键——这是用户态注入的固有限制，需要内核级筛选驱动才能覆盖。

**Q：锁屏、`Ctrl+Alt+Del`、UAC 提权窗口里能用吗？**

不能，而且**在用户态架构下无解**。这些界面运行在 Windows 的**安全桌面**（`Winlogon` 桌面）上，用户态钩子是按桌面挂载的，只能作用于当前交互桌面；连以 SYSTEM 身份运行的服务也够不到那个桌面——这是 Windows 刻意的安全设计（否则任何程序都能窃取登录密码）。

要覆盖锁屏，唯一的办法是写**内核态键盘过滤驱动**（位于 `win32k` 之下，不受桌面边界限制）。代价不小：需要内核开发能力、**EV 代码签名证书**（年费数千元）并走微软认证签名，成品也从一个 exe 变成需要安装的驱动。本项目不打算走这条路。

顺带一提：松开按键的 `keyup` 事件在切到安全桌面时也可能丢失，所以程序给"按住型"提示设了 15 秒兜底超时。

**Q：为什么在某些管理员程序里不生效？**

Windows 的 UIPI 机制禁止普通权限进程向高权限窗口发送输入。若需要覆盖任务管理器、管理员权限的安装程序等，需要以管理员身份运行本程序（可在项目属性的 manifest 中声明 `requireAdministrator`，但那样每次启动都会弹 UAC）。

**Q：笔记本合盖睡一夜，第二天醒来就不管用了（模式提示正常、托盘菜单也能用，但按键不再映射）？**

这是 **v1.0.2 修掉的一个真实 bug**，症状很有迷惑性：进程活着、热键有反应，唯独按键映射失效。

原因：Windows 会在某些情况下**静默卸载**低级键盘钩子，且不通知程序——
1. 钩子回调超过 `LowLevelHooksTimeout`（默认 300ms）
2. 系统为省电对后台进程做节流（EcoQoS）；进程被冻结后回调必然超时，钩子随即被摘掉

Modern Standby（现代待机）睡一夜正好会触发第 2 条。

修复是两手都做：

- **主动退出节能节流**（`SetProcessInformation` + `ProcessPowerThrottling`），从源头避免被冻结
- **在电源/会话事件后重建钩子**——监听 `WM_POWERBROADCAST`（唤醒）和 `WM_WTSSESSION_CHANGE`（解锁/切回），把钩子和热键重新装一遍

只在唤醒后重建是不够的（会有一段"聋"的窗口期），只退出节流也是不够的（一旦因其他原因被摘就永久失效）。每次重建都会写一行 `KeyRemap.log`（在 exe 同目录），方便确认它是否复发。

> 如果你在 v1.0.1 或更早版本遇到这个现象，升级即可。旧版只能手动重启程序。

**Q：和 PowerToys 的键盘管理器有什么区别？**

PowerToys 只能做**静态**改键，改完要重启，而且不能一键切换模式。本项目是**运行时动态切换**三套映射，且带状态提示。

**Q：多显示器时提示框出现在哪个屏幕？**

主显示器的顶部居中。如需改为"跟随鼠标所在屏幕"，修改 `ComputeGeometry()` 中的显示器选取逻辑即可。
